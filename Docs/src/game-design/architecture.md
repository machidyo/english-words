# 実装構成

**コードを読めばわかることは書かない。** ここに残すのは入口・データの流れ・なぜその構造にしたかである。判断基準は[ドキュメントの書き方](../documentation.md)を参照。

## 名前空間とフォルダー

- プロジェクト固有のものは`Assets/`直下のプロジェクト名フォルダーにまとめる
- 名前空間はフォルダー階層に合わせ、ランタイムは`<プロジェクト名>.Runtime.<機能>`とする

命名の根拠は[設計原則](../unity-guidelines/design-principles.md)と[フォルダーの命名](../unity-guidelines/naming/folders.md)にしたがう。

## シーン

- シーン: Start → Startでタイトルを非表示にして、Mainシーンを追加でロード → 完了時にMainシーンを破棄して、再びStartでタイトル表示
- リトライ: Mainを破棄したあと、タイトルを出さずにMainを再ロードする
- シーンの分け方: [画面とUI](./screens.md)で決めた方針に合わせる

Mainを追加ロード・破棄することで処理やメモリをリセットする。
BGMなど増えてきたら要検討。

**StartとMainは互いのオブジェクトを直接参照しない。** 双方が参照する`ScriptableObject`にイベントを置いて、リトライ・タイトルへ戻るの要求をそこ経由で渡す。シーンをまたぐ参照は構成変更で切れ、Prefabにも残らないため。

## 責務の分割

主要な役割を挙げる。**クラス名の一覧ではなく、責務の境界を書く。**

| 役割 | 責務 | 知ってよいもの |
| :--- | :--- | :--- |
| 単語の供給 | 辞書から出題を選ぶ | 辞書データのみ |
| モンスターの生成 | 出現タイミングと単語の割り当て | 難易度パラメーター、単語の供給 |
| 入力の解釈 | キー入力をどのモンスターに当てるか決める | 画面上のモンスター一覧 |
| モンスター個体 | 移動、表示、被弾と消滅 | 自分に割り当てられた単語 |
| 魔法の発射 | 魔法を生成し対象へ飛ばす | 発射位置と対象の位置 |
| ゲーム進行 | 開始・終了・難易度の段階 | 上記の全体 |

**「どのモンスターに当てるか」を決める権限は1か所に集約し、演出や撃破の反応は各コンポーネントが購読する。** 反応まで1か所に集めると密結合になる。

購読の配線はゲーム進行役がまとめて行う。各コンポーネントがシーンの離れた相手を`[SerializeField]`で掴み合うのを避けるため。

## データの流れ

```text
辞書データ ─→ 単語の供給 ─→ モンスター生成 ─→ モンスター個体（頭上に日本語）
                                              ↑
キーボード入力 ─→ 入力の解釈 ────────────────┘
                     └─→ 撃破 / ミス ─→ スコア・HUD
```

## 設定値の置き場所

難易度パラメーターや単語データの置き場所は[設定ファイルの配置](../unity-guidelines/config-files.md)にしたがう。マジックナンバーをコードに直接書かない。
